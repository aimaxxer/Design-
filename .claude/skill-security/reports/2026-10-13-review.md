# Skill security review, 2026-10-13

SkillSpector v2.12.0 scanned all 238 skills this project can load (`2026-10-13-full-scan.md`): 148 pass, 1 caution (score 36-50), 89 flagged. Each flagged skill then got a source review following the `skill-inspector` rubric: every HIGH or CRITICAL finding was read in context, plus a check for credential access, network calls, downloaded code, persistence and prompt injection.

**Result for the 89 flagged skills: 70 APPROVE, 19 CAUTION, 0 REJECT.** Nothing malicious was found: no credential theft, exfiltration to unknown hosts, obfuscation, hidden Unicode or hidden prompt injection. Most HIGH findings are scanner false positives:
- "Anti-refusal" phrases in normal prose (for example the shared rules block in all 36 sales skills).
- HTML comments read as "hidden instructions".
- UTF-8 byte-order marks on XML schemas.
- `AE1` "incomplete referenced artifact analysis" for local files that exist.

None of these skills are marked approved in `ledger.json` yet. The policy is that only the user approves (see `CLAUDE.md`).

## What to know first

1. **HyperFrames reads your Claude Code login token.** The `hyperframes` router skill makes Claude run `npx hyperframes usage --json` at the start of every video. That CLI reads the Claude Code OAuth token (macOS keychain or `~/.claude/.credentials.json`) and sends it as a bearer token to `api.anthropic.com/api/oauth/usage` to show plan usage. In the reviewed source (commit `e8eb358`, `packages/cli/src/utils/harnessUsage.ts`) it goes only to Anthropic, with redirects refused. But the skill doesn't disclose this, and `npx` runs whatever npm build is current, which wasn't reviewed.
2. **HyperFrames sends things to HeyGen by default.** After renders, `hyperframes-cli` has Claude send feedback and "missing feature" reports (paraphrasing what you asked for) to HeyGen. `media-use` has PostHog telemetry on by default, tied to your HeyGen account email; opt out with `HYPERFRAMES_NO_TELEMETRY=1` or `DO_NOT_TRACK=1`. Its background-music path pip-installs unpinned `torch`/`transformers` into your Python.
3. **Unpinned remote code.** HyperFrames upgrades itself with `npx hyperframes@latest upgrade` and bumps your project's pin "rather than relaying it to the user". Its registry pulls from GitHub `main`. Expo skills run `npx --yes eas-cli@latest`, and a feedback step runs `npx --yes submit-expo-feedback@latest "<text>"`. The four project marketplaces in `.claude/settings.json` are also unpinned, so plugin updates arrive from upstream `main`. The SessionStart hook rescans them whenever their commit moves.
4. **Expo's plugin hook is fine as configured.** It runs after every skill call but keeps only an `expo:` skill name. Telemetry is off unless you opt in (`EXPO_SKILLS_TELEMETRY=1` or `~/.expo-skills/opt-in`); it's off here. `eas-simulator` can start paid EAS cloud sessions without asking again, and `eas-workflows` pre-approves every `node` command while active.
5. **Spending.** `design-taste-frontend` says Claude must use any image-generation tool available and not ask, which can spend Higgsfield, ElevenLabs or Figma credits. `product-launch-video` spends any Gemini, Google or OpenRouter key in the environment.
